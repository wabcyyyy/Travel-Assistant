# 合规与开源安全说明

> 适用范围：本仓库开源 / 作品集展示 / 校招投递前的自检。  
> 定位：**本地演示系统**，不是已上线生产服务。本文只描述「已做」与「必须由你自行完成」的事项。

---

## 1. 密钥与配置（最重要）

### 1.1 仓库原则

| 允许入库 | 禁止入库 |
|----------|----------|
| `.env.example` 占位符 | 任何真实 `LLM_API_KEY` / 高德 Key / Unsplash Key |
| 非敏感默认超时、开关 | `JWT_SECRET` 真实值、`AGENT_INTERNAL_TOKEN` 真实值 |
| 文档中的脱敏示例 | MySQL 密码、JWT 真 Token、`Authorization: Bearer ...` |

根目录与各端 `.env`、`.test-report/`、`.test-token.txt`、`.test-user.txt`、`dist/`、`target/` 已在 `.gitignore`。

### 1.2 开源 / 推送前强制清单

在控制台**全部 rotate**（旧 Key 视为已泄露）：

- [ ] 阿里云百炼 / DashScope `LLM_API_KEY`
- [ ] 高德 Web 服务 Key（`AMAP_WEB_KEY`）
- [ ] 高德 JS API Key + 安全密钥（`VITE_AMAP_*`，并配置域名白名单 + 配额）
- [ ] Unsplash Access Key
- [ ] 如使用 Google Maps：Google Cloud Key + 限制 HTTP referrer / IP
- [ ] 本地 `JWT_SECRET`、`AGENT_INTERNAL_TOKEN` 改为新的随机值（勿沿用示例）
- [ ] MySQL：非 root 账号 + 强口令；演示库与生产库分离
- [ ] 执行 `pwsh scripts/check-secrets.ps1` 且通过
- [ ] 确认 `git status` / `git ls-files` 中无 `.env`、token 文件
- [ ] 若历史上曾 `git add .env`：**即使已删除文件，历史里仍有 Key**，必须在远端 rotate，并考虑 `git filter-repo` 清洗历史后再开源

### 1.3 本机已执行的清理

- 本地 JWT / 用户 dump 与 `.test-report/` 联调产物已移出仓库树（备份在 `%TEMP%\travel-assistant-local-artifacts\`，**勿提交、勿截图密钥**）。
- 跟踪源文件扫描：未发现硬编码真实 LLM/高德 Key（仅 `.env` 本机文件含真实值，且未跟踪）。

## 2. 第三方数据与内容合规

| 数据源 | 用途 | 合规要点 |
|--------|------|----------|
| 高德 Web API / JS API / MCP | POI、坐标、路线、静态图 | 遵守高德开放平台服务条款；**Key 不得提供给第三方代理请求**；注意日配额与展示规范 |
| Unsplash API | POI 实景图 | 遵守 Unsplash API 指南；按要求展示署名/链接；勿把 Access Key 打进可被匿名滥用的代理 |
| Wikipedia / Wikimedia | 景点缩略图 | 遵守对应版权与署名；页面展示时保留出处 |
| Wikivoyage（CC BY-SA） | POI 描述等 listing | **署名 + 相同方式共享**；`source` 字段已标 wikivoyage，若公开衍生数据库需评估 SA 义务 |
| OSM Nominatim | 国外坐标兜底 | UA 需可识别可联系；遵守 1 req/s 量级与缓存政策；勿做批量爬虫 |
| Google Places / Routes | 国外 POI/路线（可选） | 遵守 Google Maps Platform 条款；**禁止超期缓存** Places 内容 |
| LLM（通义千问等） | 行程生成/对话 | 用户行程会送第三方推理服务；公开部署需隐私说明；控制成本与滥用 |

**本项目未做法务审查。** 若要商用或公开 SaaS，需重新评估各 ToS 与《个人信息保护法》相关义务。

## 3. 运行时安全边界（已实现 / 已知缺口）

### 已实现

- JWT 必填强校验（`ENFORCE_SECRET_CHECK`，默认开）
- Java ↔ Agent `AGENT_INTERNAL_TOKEN`；Python 非回环 + 空 Token fail-fast
- 登录/注册限速；仅 `TRUSTED_PROXIES` 信任 `X-Forwarded-For`
- 密码 8–32 位且含字母+数字；BCrypt
- `/api/amap/geocode`、`/api/amap/poi` 需登录；图片代理 host 白名单 + 有界缓存
- 生成类错误不外泄内部异常原文；Trace 脱敏 URL key / Bearer
- **JWT 服务端吊销**：`POST /api/auth/logout` 写入 Redis 黑名单（token SHA-256 + 剩余 TTL）；过滤器拒绝已吊销 token；Redis 故障降级本机 Map
- **HttpOnly Cookie 会话**（`TA_AUTH`）：主凭据不可被 JS 读取；写请求 Origin 白名单；`AUTH_COOKIE_SECURE` 控制 Secure 标志

### 已知缺口（开源说明里请如实写）

- 登录响应体仍含 token（脚本/联调用）；若页面被 XSS，内存中的 token 仍有泄露面
- 无多端「会话列表」管理（只能 logout 当前 token）
- 单机进程内限流，多实例需外置存储
- 演示环境可能仍使用本地弱口令数据库（**开源请勿复用**）

## 4. 建议的开源发布流程

```text
1. 本地 rotate 全部第三方 Key + JWT/内部 Token
2. pwsh scripts/check-secrets.ps1
3. git ls-files | findstr /i ".env token test-report"   # 应无输出
4. 确认 README 含「已知局限」与本文链接
5. 新建 public 仓库，仅 push 干净历史（若曾泄密先 filter-repo）
6. 高德/JS Key 控制台：域名白名单仅你的演示域名，设配额告警
```
