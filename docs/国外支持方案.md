# 国外目的地支持方案：GeoProvider 双提供商 + 零 LLM 知识库采集

> 状态：**全部四阶段已实施**（阶段 1 零 LLM 采集器 / 阶段 2 Python GeoProvider / 阶段 3 国外知识库采集（Nominatim 免 key）/ 阶段 4 前端 Leaflet+OSM 地图切换）。
> 说明：Google Places/Routes 需绑卡启用，项目以 **OSM Nominatim 免 key** 作为国外地理数据源落地（真实坐标、零费用）；将来拿到 Google key 可平滑升级（key 门控已就位）。
> 目标：国外地点从"能生成但裸奔"升级为"可落坐标、有路线、有地图、可选知识库证据"。

---

## 一、现状与能力缺口

当前国外地点（如巴黎/东京）**能生成但缺地理能力**：

| 能力 | 国内 | 国外现状 |
| --- | --- | --- |
| 生成内容 | LLM 开放模式 + 高德落坐标 | ✅ 生成（LLM 知识） |
| 坐标落地 | 高德 POI 落坐标 | ❌ 无（高德仅中国） |
| 路线校验/附近推荐 | 高德/知识库坐标 | ❌ 无 |
| 前端地图/静态图 | 高德 JSAPI/staticmap | ❌ 无 |
| 知识库证据 | 6 城三源采集 | ❌ 无（空候选，如实降级） |

核心结论：**换地图提供商是根因修复；知识库是可选加强项（LLM-only 下不是前提）**。

## 二、GeoProvider 双提供商架构

### 原则

- 抽象 `GeoProvider` 接口，**按目的地路由**：国内 → `AmapProvider`（现状不动），国外 → `GoogleProvider`；
- **实现采用 provider chain（高德 → Google）**：高德命中即返回（国内零回归），空结果才切 Google
  （国外自动接管），无需城市分类表，规避"未知中国城市被误判国外"的回归风险；
- 外部契约（`/v1/generate`、`/v1/generate-day`、前端 API）**不变**，路由细节收敛在 Python 数据面；
- 研究 Agent / 开放模式 / 路线 / 附近推荐 / 前端共用同一 Provider 分发。
- **Google 需绑卡启用（Places/Routes 为付费 API，$200/月免费额度）**：无卡/未绑卡时，
  自动落到 **OSM Nominatim 免 key 兜底**（真实坐标，POI 语义弱于 Places，路线退回坐标估算）。

### 已实施（阶段 2，Python 侧）

| 能力 | 实现 | 效果 |
| --- | --- | --- |
| POI 检索兜底 | [tools.py `search_amap_poi`](../../travel-agent-python/app/agent/tools.py)：MCP → REST → Google Places | 国外 POI 检索可命中 |
| 国外落坐标 | [day_stream.py `_amap_ground`](../../travel-agent-python/app/agent/day_stream.py) 复用 `search_amap_poi` → Google | **国外生成后坐标非空** |
| 路线兜底 | [route_service.py](../../travel-agent-python/app/agent/route_service.py)：高德 → Google Routes → 坐标估算 | 国外路线 `source=google` |
| Google 客户端 | [google_maps.py](../../travel-agent-python/app/integrations/google_maps.py)：Places Text Search + Routes computeRoutes + 契约归一化（`source=google.places`） | key 门控，未配置保持现状 |
| 配置 | `GOOGLE_MAPS_API_KEY` / `GOOGLE_MAPS_TIMEOUT`（[config.py](../../travel-agent-python/app/common/config.py) + `.env.example`） | 默认空 = 行为不变 |

关键链路（国外城市）：`_amap_ground(item)` → `search_amap_poi` → 高德空 → Google Places 命中 → 真实坐标落 item → 后续路线/地图可用。

## 三、零 LLM 采集器（已实施）

`sql/enrich_pois.py` 已改为**零 LLM 默认模式**：

```bash
python sql/enrich_pois.py --cities 北京          # 默认：Wikivoyage 原文直接入库，零模型成本
python sql/enrich_pois.py --cities 北京 --with-llm  # 可选：LLM 翻译+补齐（高质量模式）
```

- 新增 `build_wv_records`：以 Wikivoyage 原文（名称/描述/价格/时间）构建记录，`source=wikivoyage`（无 +llm）；
- 每城约 1-3 分钟纯 API 调用、零模型费用；`--with-llm` 保留原 LLM 翻译/补齐路径；
- 已知取舍（如实降级）：英文原文 + 中文查询在 hashed 词袋向量下检索命中弱；缺 `tags/open_time/duration_min`（tags 用规则推导，其余留空）。

## 四、国外知识库采集（已实施：Nominatim 免 key）

`enrich_pois.py` 已支持国外城市（CITY_CONFIG 中无 adcode 自动识别，内置 巴黎/东京/纽约/伦敦）：

```bash
python sql/enrich_pois.py --cities 巴黎 东京   # 国外：Nominatim 免 key + Wikivoyage 原文，零 LLM
```

- `fetch_nominatim_pois`：按品类关键词 + viewbox 边界检索真实坐标（1 req/s 限流，source=nominatim）；
- `collect_wv_records`：Wikivoyage listing（零 LLM 原文或 --with-llm 翻译）国内/国外共用；
- 国内城市仍走高德（需 AMAP_WEB_KEY），国外无需任何 key；
- 权威来源白名单已加 `nominatim`，引用落地照常背书。

语言对齐要点：Wikivoyage 原文多为英文，中文查询 + hashed 词袋向量下检索命中弱——
如需国外知识库服务中文查询，切 `RAG_EMBEDDING_PROVIDER=sentence-transformers`（bge-m3 多语）
或改用 zh.wikivoyage 采集源（模型/文档版本变化需全量重建索引）。

## 七、风险与取舍

- **成本**：Google Maps/Places 按量计费 → 阶段 2 只落坐标/路线（低频），静态图/前端瓦片可选免 key 方案；
- **检索质量**：英文文档 + 中文查询是主要风险 → 阶段 3 绑定 bge-m3，不做语义升级则国外知识库价值有限；
- **口径变化**：货币、季节、消费数据按目的地区分，避免"人民币估算"误导国外预算；
- **明确不做**：为国外单独建 LLM 网关、离线地图瓦片自托管、多提供商热切换 UI。
