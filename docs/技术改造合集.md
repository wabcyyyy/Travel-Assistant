## 1. 进程内状态 → Redis 分布式状态

### 1.1 动机

登录失败限速、注册限速、行程日生成锁、恢复任务续跑去重原先都在 **JVM `ConcurrentHashMap`**。

| 问题 | 后果 |
|------|------|
| 多实例部署 | 限速被绕过：打到实例 B 可重置计数 |
| 双实例同时 planDays | 同一天可能并发生成 → 落库竞态 / 重复 LLM 成本 |
| 恢复任务双节点扫描 | 同一 itinerary 被 resume 两次 |
| 进程重启 | 限速与去重标记丢失 |
| 集合膨胀 | 需手工清扫 |

### 1.2 方案

新增 **`DistributedStateService`**（Java）：

| 原语 | Redis | 本地兜底 |
|------|-------|----------|
| 限速计数 | 见 §2 滑动窗口 | 时间戳队列 |
| 互斥标记 / 锁 | `SET key 1 NX EX` | `putIfAbsent` + TTL |

**Redis 故障**：自动降级进程内；多实例必须保证 Redis 可用。

| 场景 | Key | TTL |
|------|-----|-----|
| 登录失败限速 | `auth:login:fail:{ip}\|{user}` | 15 min |
| 注册限速 | `auth:register:{ip}` | 15 min |
| 日生成锁 | `gen:day:{itineraryId}:{dayNo}` | 5 min |
| 续跑去重 | `gen:resume:{itineraryId}` | 10 min |
| JWT 吊销 | `auth:jwt:revoked:{sha256}` | token 剩余寿命 |

配置：`app.state.prefer-redis`（默认 `true`）。

### 1.3 前后对比

| 维度 | 改造前 | 改造后 |
|------|--------|--------|
| 登录限速作用域 | 单 JVM | 集群共享（Redis） |
| 同日并发生成防护 | 仅同 JVM `synchronized` | 跨实例 SETNX |
| 续跑双节点重复拉起 | 各节点独立 Map | 一节点占用，其它跳过 |
| 重启后限速状态 | 清零 | 仍在 Redis（窗口内） |
| 状态可观测 | 散落静态字段 | 统一 key 前缀 |

**成本**：限速/锁路径多 1 次 Redis RTT（亚毫秒～数 ms），相对 LLM 调用可忽略。

### 1.4 代码清单

| 文件 | 变更 |
|------|------|
| `common/DistributedStateService.java` | **新增** |
| `UserServiceImpl` | 登录/注册限速 |
| `ItineraryAsyncPlanner` | 日锁 SETNX + finally |
| `ItineraryStatusRecovery` | 续跑标记 |
| `TokenRevocationService` | JWT 黑名单（既有，同属 Redis 状态） |

### 1.5 简历表述

> 将登录/注册限速、行程日锁与续跑去重从 JVM 静态 Map 迁移至 Redis（SETNX TTL + 滑动窗口），支持多实例水平扩展；Redis 故障自动降级进程内，单测覆盖本地与 Redis 两条路径。

**不要写**：「强一致分布式锁 / Redlock」——当前为 SETNX + TTL 租约式互斥。

## 2. 固定窗口限流 → 滑动窗口

### 2.1 动机

固定窗口（`INCR` + 整点过期）在**窗口边界**可出现「双倍突发」：

```text
窗口 [0, 60s)，阈值 5
t=59s 连打 5 次 → 通过
t=61s 新窗口清零 → 再打 5 次 → 通过
实际 2s 内 10 次，超过阈值 2 倍
```

### 2.2 方案

| 实现 | 结构 |
|------|------|
| **Redis** | ZSet：`score=时间戳`，member 带随机后缀防同毫秒去重；`ZREMRANGEBYSCORE` 裁剪；`ZCARD` |
| **本地** | `ConcurrentLinkedDeque<Long>` + 裁剪；单 key cap 10k |

API：`increment(key, window)` / `getCount(key, window)` / `resetCounter(key)`。

### 2.3 对比

| 维度 | 固定窗口 | 滑动窗口 |
|------|----------|----------|
| 边界双倍突发 | 有 | **无** |
| Redis 结构 | STRING INCR | ZSET |
| 单次成本 | ~2 RTT | ~3–4 RTT |
| 内存 | O(1)/key | O(窗口内事件数) |

| 场景（阈值 5 / 15min） | 固定 | 滑动 |
|------------------------|------|------|
| 连续 5 次失败 | 第 6 次 429 | 第 6 次 429 |
| 59s 末 5 次 + 61s 初 5 次 | **允许** | **第 6 次起拒绝** |

### 2.4 简历表述

> 将登录/注册限流从 Redis 固定窗口升级为滑动窗口（ZSet 时间戳裁剪），消除窗口边界双倍突发；本地降级为时间戳队列。

**不要写**：「彻底防住爆破」——仍无验证码/账号锁定。

## 3. RestTemplate → RestClient

### 3.1 动机

- `RestTemplate` 为维护模式；Spring 6 推荐 `RestClient` / `WebClient`  
- 超时分散：配置类 + Controller 内 `new RestTemplate`  
- `exchange` + `HttpEntity` 样板多  

### 3.2 方案

`RestClientConfig`：

| Bean | 用途 | 超时 |
|------|------|------|
| `restClient` | Agent / 高德 / 探针 | connect 3s · read 180s |
| `imageRestClient` | 图片代理 | connect 2.5s · read 7s |

```java
// 改造后
restClient.post().uri(url)
    .headers(h -> { ... })
    .body(body)
    .retrieve()
    .body(new ParameterizedTypeReference<Result<JsonNode>>() {});
```

**HTTP 契约不变**：URL、鉴权头、Result 信封、502 语义。

### 3.3 对比

| 维度 | RestTemplate | RestClient |
|------|--------------|------------|
| Spring 官方状态 | 维护模式 | **推荐同步客户端** |
| 超时配置点 | 多处 | **2 个 Bean** |
| 演进路径 | 断层 | 同源 RestClient/WebClient |

**性能**：底层仍为 `SimpleClientHttpRequestFactory`，稳态延迟量级相当；收益在工程演进。**勿写性能提升 %。**

### 3.4 简历表述

> 将 Java 出站 HTTP 从维护模式的 RestTemplate 迁移到 Spring 6 RestClient，统一 Agent/地图/图片客户端与超时策略，保持业务信封与错误语义不变。

## 4. Agent 出站熔断 + 分级重试

### 4.1 动机

| 问题 | 后果 |
|------|------|
| Agent 宕机仍打满读超时 | Tomcat 线程堆积 |
| 无快速失败 | 用户长时间转圈 |
| 盲目重试 generate | **双倍 LLM 计费** |

### 4.2 方案

`SimpleCircuitBreaker`（三态）：

```text
CLOSED ──连续失败≥N──► OPEN ──超时 T──► HALF_OPEN（单探针）
   ▲                                        │成功→CLOSED
   └────────────────────────────────────────┘失败→OPEN
```

| 配置 | 默认 |
|------|------|
| `app.agent.circuit.failure-threshold` | 5 |
| `app.agent.circuit.open-seconds` | 30 |

**分级重试：**

| 调用 | 瞬时失败重试 | 原因 |
|------|--------------|------|
| GET metrics/usage | 是（2 次） | 幂等只读 |
| POST clarify/chat/plan-context 等 | 是（2 次） | 无副作用决策 |
| **generate / generate-day** | **否** | 烧 LLM token |

### 4.3 故障行为对比

| 场景 | 前 | 后 |
|------|----|----|
| Agent 宕机 | 每次等满 180s | 熔断后**快速 502** |
| 读接口抖动 | 直接 502 | 自动重试 1 次 |
| Agent 恢复 | 无感知 | 半开探针成功后 CLOSED |
| generate 抖动 | 一次失败 | **仍不重试** |

### 4.4 简历表述

> 为 Java→Agent 的 RestClient 调用增加三态熔断与分级重试：读接口瞬时失败自动重试，生成接口绝不重试以避免 LLM 双倍计费；熔断打开后快速失败，降低故障时对 Tomcat 线程池的拖垮风险。

**不要写**：「彻底解决雪崩」——无舱壁、无全局限流。

## 5. pymysql 裸连 → 连接池

### 5.1 动机

`poi_repository` / `enrich_pois` 每次 `pymysql.connect(...)`：

- 每次查询新建 TCP + 握手  
- 无连接上限  
- 无 ping 自愈  
- 超时参数多处复制  

### 5.2 方案

`app/common/db_pool.py`：

| 能力 | 实现 |
|------|------|
| 复用 | 线程安全队列 + 惰性建连 |
| 上限 | `DB_POOL_MAX`（默认 10） |
| 自愈 | 取出 `ping()`，坏连接销毁重建 |
| 归还 | `connection()` 成功回池；异常销毁 |
| 耗尽 | 阻塞 5s 后 `TimeoutError`（仓储吞掉返回空） |

```python
with db_pool.connection() as conn:
    with conn.cursor() as cursor:
        cursor.execute(sql, params)
```

### 5.3 对比（结构估算，非压测）

| 维度 | 前 | 后 |
|------|----|----|
| 1000 次顺序查询建连 | 最多 **1000** | 最多 **~10**（池满后复用） |
| 并发连接上限 | 无 | ≤ `DB_POOL_MAX` |
| 空闲断连 | 下次失败 | ping 自愈 |

### 5.4 简历表述

> 为知识库仓储与数据管线引入线程安全 MySQL 连接池（惰性建连、ping 自愈、异常销毁、可配置上限），消除每次查询新建 TCP 的开销，将连接数约束在可预期范围。

**不要写**：「QPS 提升 xx%」——无对照压测。

## 6. LLM httpx 连接池与超时分层

### 6.1 动机

每次 `httpx.post` / `httpx.stream` 新建连接：重复握手、无连接上限、connect/read 超时一刀切。

### 6.2 方案

进程内共享 `httpx.Client`：

| 项 | 配置 |
|----|------|
| max_connections | `LLM_POOL_MAX_CONNECTIONS`（默认 20） |
| max_keepalive | `LLM_POOL_MAX_KEEPALIVE`（默认 10） |
| keepalive_expiry | 30s |
| connect/pool/write | `LLM_CONNECT_TIMEOUT`（默认 5s） |
| read | `LLM_TIMEOUT`，可被 run deadline 收紧 |

### 6.3 对比

| 维度 | 前 | 后 |
|------|----|----|
| TCP/TLS | 每请求新建 | **池内复用** |
| 连接上限 | 无 | ≤ 20 |
| 超时 | 单一 total | **connect/read 分层** |

### 6.4 简历表述

> 为 LLM 网关客户端引入进程内 httpx 连接池（keep-alive + 连接上限）与 connect/read 分层超时，消除高频调用下的重复握手，并限制对上游的连接扇出。

## 7. docker-compose 本地编排

### 7.1 动机

仅 Windows `start-all.cmd` + 本机手工装 MySQL/Redis，跨 OS / 新同学 / CI 成本高。

### 7.2 方案

```bash
docker compose up -d mysql redis          # 默认：仅中间件 + healthcheck
docker compose --profile apps up -d --build  # 可选：容器化三端
```

| 服务 | 端口 | 说明 |
|------|------|------|
| mysql | 3306 | utf8mb4；volume；healthcheck |
| redis | **6380→6379** | 与项目默认对齐 |
| agent / backend / frontend | 8000/8080/5173 | profile `apps` |

**取舍**：默认不强制容器化应用（本地热重载、模型路径、`.env` 更顺手）。

### 7.3 对比

| 维度 | 前 | 后 |
|------|----|----|
| 起依赖 | 装 MySQL/Redis + 手工建库 | `compose up -d mysql redis` |
| 跨 OS | Windows 脚本为主 | 任意 Docker 机器 |
| 健康检查 | 手工 curl | compose healthcheck |

### 7.4 简历表述

> 补充 docker-compose 与三端 Dockerfile：MySQL/Redis 一键健康检查启动，应用可选 profile 容器化；降低跨机器环境成本，保留宿主机热重载开发路径。

**不要写**：「生产 K8s / CI 镜像发布」。

## 8. 登录不回 token · 多端会话 · 指标

### 8.1 登录响应不再携带 JWT

| 维度 | 前 | 后 |
|------|----|----|
| Login body | 含 `token` | `token` 恒为 null（字段保留兼容） |
| 凭据通道 | Cookie + body | **仅 HttpOnly Cookie** |
| XSS 面 | 响应体/内存可读 | 仅 Cookie（HttpOnly） |

实现：`AuthSessionHolder` 线程局部传递 token → Cookie 写入；前端不再 `setToken` 入内存/localStorage。

### 8.2 多端会话

`UserSessionService`：`username → jti 集合` + `jti → token` 索引（Redis 优先，本地兜底）。

| 接口 | 作用 |
|------|------|
| 登录 | `register(username, jti, token, ttl)` |
| `POST /api/auth/logout` | 吊销当前 + 移除 jti |
| `POST /api/auth/logout-all` | 吊销该用户全部已登记会话 |

### 8.3 可观测

| 指标 | 位置 |
|------|------|
| Python `db_pool` created/idle/max | Agent `/v1/metrics` → `db_pool` |
| Java 熔断 state/threshold | Admin `agent-metrics` → `circuitBreaker` |

### 8.4 简历表述

> 登录凭据收敛为 HttpOnly Cookie（响应体不再回传 JWT）；用 Redis 维护 username→jti 多端会话，支持单设备登出与 logout-all；指标暴露连接池与熔断状态。

## 11. 遗留清单（诚实口径）

| 项 | 说明 |
|----|------|
| 分布式锁 owner / Lua 解锁 | unmark 为直接 DEL，极端可误删他人锁 |
| 舱壁 Bulkhead | 熔断外仍可加并发信号量 |
| 滑动窗口非 Lua 原子 | ZADD/ZREMRANGE/ZCARD 多 RTT，可有轻微高估（偏安全） |
| LLM AsyncClient | 仍同步 httpx；高并发可评估 async 路径 |
| 无出站 Micrometer 指标 | 可观察 RestClient / 连接池 / 熔断状态 |
| CI | 未接 `compose config` + 单测流水线 |
| 生产级 | 本合集面向演示/作品工程化，非生产 SaaS |

## 12. 面试追问速查

| 问题 | 要点 |
|------|------|
| 为什么不用 Redisson？ | 依赖面控制；SETNX+TTL 覆盖本场景；要续约再上 |
| Redis 挂了限速？ | 单机本地兜底；多实例退化为每实例限速，不 500 |
| 为什么 RestClient 不 WebClient？ | MVC 阻塞栈；WebClient 需响应式改造 |
| 为什么不重试 generate？ | LLM 非幂等且计费；业务层状态机/恢复任务决定续跑 |
| 池大小怎么定？ | Agent 只读默认 10；生产按 QPS×持连时间与 max_connections 核算 |
| 滑动窗口 vs 令牌桶？ | 登录是「窗口内失败次数」语义，滑动窗口更贴切 |
| compose 为何默认不起应用？ | 模型/热重载/.env；profile 留给演示 |
