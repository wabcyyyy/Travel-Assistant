## 1. 项目可取点

这些是真亮点，面试可以讲，但别加戏：

1. **问题意识清晰**：把「LLM 会编造」当第一性问题，用引用式生成 + 溯源字段（`source`/核验状态）把「模型说的」和「知识库说的」在数据层区分开，比「接个 ChatGPT API」强一个量级。
2. **降级语义有设计**：精排挂→融合排序、语义挂→词法、DB 挂→Chroma 元数据、LLM 挂→待研究草案，且写 trace/metrics。不是静默吞错。
3. **RAG 工程有分层**：查询路由（枚举/BM25/混合）+ 语义缓存（空/降级不缓存）+ RRF + bge-m3 + cross-encoder 精排 + 轻量 GraphRAG 近邻，不是「向量库一锅炖」。
4. **成本/预算硬闸**：`run_limits.py` 对 Deadline / LLM 次数 / Token 预算做执行期约束，不是只写在 Prompt 里。
5. **水平越权基本做对了**：`findOwnedMain` / `findOwnedItem` / export 任务 `userId.equals` 一致，不是 IDOR 裸奔。
6. **安全收口有动作**：登录限速、BCrypt、参数编码构建高德 URL、图片代理 host 白名单、trace 脱敏、非回环 + 空 internal token 时 fail-fast、生成任务独立 AbortPolicy 池。
7. **测试结构分层**：离线 mock 单测 / 真实 LLM 评测 / 检索评测 / Java 状态机测试分开报告，避免「自测全绿」骗自己。
8. **有自审文化**：`docs/代码审计报告.md` 记录了 Critical/High 及多轮修复——这在学生项目里少见，说明你能发现并收敛问题。

## 2. 核心问题与不足

### 2.1 P0 — 简历/开源前必须处理

#### 2.1.1 本地明文密钥与会话令牌暴露面过大

| 位置 | 风险 |
|---|---|
| 根目录 `.env` | 高德 Web Key、MySQL root 密码、Unsplash Key |
| `travel-agent-python/.env` | **完整 LLM API Key（可烧钱）**、DB 密码、绝对路径模型目录 |
| `travel-frontend-vue/.env` | 高德 JS Key + security code |
| `.test-token.txt`、`.test-report/token.txt` | 可用 JWT 明文；`.test-report/` **未 gitignore** |

`.env` 已 ignore 且未被 git 跟踪（这点做对了），但：

- `.test-token.txt` / `.test-report/` 是 untracked，**误 `git add .` 就会进库**；
- LLM Key 一旦泄露 = 直接烧钱/滥用；
- 校招若展示仓库或截图日志，面试官第一问就是「Key 会不会泄」。

> 说明：本报告不抄写任何真实 Key/密码/Token 明文，只标注位置与风险。

#### 2.1.2 高德/Unsplash 免鉴权代理端点 = 白嫖你的配额

`SecurityConfig` 中以下端点 `permitAll`：

```text
/api/amap/staticmap
/api/amap/poi-photo
/api/amap/image
/api/amap/geocode
/api/amap/poi
```

- `geocode` / `poi` 是完整 Web API 代理，**任何匿名流量都能打**；
- `poi-photo` 还会带 Unsplash Access Key 去打第三方；
- `photoCache` 是无界 `ConcurrentHashMap`，高基数 POI 名可撑爆堆。

**后果**：配额耗尽、账单、被刷成开放代理；合规上还违反高德「Key 不得提供给第三方/代理他人请求」类条款。

#### 2.1.3 服务间鉴权默认可关，且 Java 侧默认空 token

Python 已对「非回环 + 空 token」fail-fast，但 Java `AGENT_INTERNAL_TOKEN` 默认空。

本机 `127.0.0.1` 演示可接受；一旦 Agent 端口被转发/容器互通，生成接口就是**匿名烧 LLM**。

### 2.2 P1 — 架构 / 业务逻辑硬伤

#### 2.2.1 三套生成编排并存（项目自审也承认了）

`workflow.py` / `day_stream.py` / `day_workflow.py` 三份相似编排：  
`needs_hotel` 口径、fallback 真实性、ReferencePool 过滤曾不一致。

面试官会打：

- 「为什么不收敛成一个内核？」
- 「改动三处会不会改漏？」

历史 bug（审计 #16/#24/#26）就是证据。

#### 2.2.2 Java 层价值被追问时站不住

链路：Vue → Java → Python → LLM。

| 层 | 实际职责 |
|---|---|
| Java | 鉴权、状态机、缓存、PDF、转发 |
| Python | 全部智能 |

若面试官问「为什么要两套后端」，只答「三端分离」不够——那只是部署形态，不是业务必要性。  
单人/校招项目里这是**复杂度债**，不是加分架构。

#### 2.2.3 「实时酒店价」名不副实

`LIVE_PRICE_SEARCH` 默认 `false`；预算链实际是：

> 联网实时价（默认关）→ 知识库基准价 × 季节系数

README/简历若写「联网实时价」，会被打穿。  
预算看板是**估算引擎**，不是 OTA 报价。

#### 2.2.4 开放模式行程项大量「待确认」是产品诚实，也是产品力缺口

LLM-only 选点 + 高德落坐标 + 待复核标签——诚实。

但用户拿到的是「可能不存在/已关门/价格错」的行程。  
Reflection 校验时间/路线，**验不了「这家店还在不在」**。  
「6/6 引用落地、faithfulness 1.0」是**小样本 + 固定模型**评测，不能外推到全量。

#### 2.2.5 预算模型过度简化

- 门票/餐饮统一 `unit × persons`，儿童/老人票、餐厅桌数不建模；
- 交通 = 城市默认日均 × 天 × 人，不含跨城/打车/机票；
- 酒店按房型容量 `ceil(persons/capacity)` 晚次累加，和「全程同一家」产品口径耦合，转点多城市会错。

### 2.3 P1 — 接口与数据安全

#### 2.3.1 JWT 无吊销

- Token 只含 `sub=username`，无 `jti`、无黑名单/版本号；
- 禁用用户靠每次请求回查 DB（安全上 OK），但 **logout 纯前端**，token 在 24h 内仍有效；
- `JWT_SECRET` 未配置时用**进程内随机密钥**——重启全掉线，多实例直接互不认账。

#### 2.3.2 Token 放 `localStorage`

XSS 可直接读走。

markdown 已做 escape（这点好），但 Element Plus / `v-html` 其它入口、第三方脚本仍是攻击面。  
校招标准答案：**HttpOnly Cookie + CSRF**，或至少说清 tradeoff。

#### 2.3.3 登录限流可被绕过 + 注册可枚举

- `X-Forwarded-For` **盲信第一段**，伪造即可重置计数；
- 限流是进程内 Map，多实例无效；
- 注册「用户名已存在」= 用户名枚举；
- 密码策略仅 `[\w!@#$%^&*]+` 长度 6–32，**无复杂度**，`123456` 合法。

#### 2.3.4 每次鉴权查库

`JwtAuthenticationFilter` 每请求 `selectOne` 用户。  
换禁用即时生效，代价是 QPS 上限被 MySQL 绑死。  
可选：短 TTL 本地缓存 + 失效事件。

### 2.4 P1 — 第三方服务合规风险

#### 2.4.1 数据采集/存储可能踩 ToS

| 数据源 | 风险点 |
|---|---|
| 高德 Web API | Key 代理化；批量采集入库是否在「自用检索」边界内 |
| Unsplash API | 官方禁止某些缓存/再分发场景；access key 被匿名端点间接消耗 |
| Wikivoyage | **CC BY-SA**：`source` 字段署名偏弱，**ShareAlike** 对衍生库义务未说清 |
| OSM Nominatim | UA 有，但官方要求**可联系的邮箱**、严格限流；当前 UA 过简 |
| Google Places | 常见坑：**长期缓存 Places 内容** 可能违反 Google Maps Platform 条款 |
| 维基图片 | 需署名；未见页面级 attribution |

面试官问「你的 POI 库能不能商用/上线」时，现在答不圆。

#### 2.4.2 本地 LLM Key + 用户行程内容送第三方

阿里云百炼等合规（数据出境/训练使用）用户侧通常不可见，但产品层面要有隐私说明。目前没有。

---

### 2.5 P2 — 性能与工程

#### 2.5.1 长超时同步链路

Java RestTemplate 对 Agent 读超时可达 180s；Agent Deadline 90s。  
用户侧靠轮询。并发 4 个生成线程 + 队列 20，再满 AbortPolicy——**能扛一点，但没有真正压测证据进主路径**。

#### 2.5.2 重型依赖同进程

bge-m3 + reranker + Chroma + LangGraph 与 FastAPI 同机；冷启动/内存/并发检索会互相踩。没有独立向量服务与读写分离。

#### 2.5.3 测试「绿」的假阳性风险

项目自审已写：H4 语义缓存近似命中曾是死代码、多测 mock 通过生产坏。  
说明**单测覆盖率 ≠ 集成正确性**。「223 passed」不能当质量背书。

#### 2.5.4 工程卫生

`.test-report/` 堆满 JSON/Token/PDF、logs、kill 脚本、绝对路径模型目录——不适合当作品集仓库直接展示。

## 3. 针对性改进建议

| 问题 | 可落地改法 |
|---|---|
| 密钥泄露 | 1) 全库轮换 LLM/高德/Unsplash Key；2) gitignore 加 `.test-report/`、`*.token`；3) pre-commit 扫 `sk-`、`Bearer`；4) README 写「提交前必须 rotate」 |
| 匿名高德代理 | `geocode`/`poi` 改需鉴权；`staticmap`/`image` 加签名或短时效 token + 限流；`photoCache` 上限 + LRU |
| Internal token | 两端默认生成强随机 token，启动时打印一次到日志/本地文件；空 token 一律拒绝启动（不只 Python） |
| JWT | 加 `jti` + Redis 吊销；secret 强制非空；评估 HttpOnly Cookie；logout 真吊销 |
| 限流 | 忽略未受信的 `X-Forwarded-For`（仅信任反代 IP）；注册同频限流；用户名枚举改为统一错误文案 |
| 三编排 | 收敛为「单一 plan 生成内核」+ day/整段适配层；写集成测试锁行为 |
| 两后端 | 简历里主动讲 tradeoff：「演示为何拆 Java 网关/鉴权/异步任务；生产可合并或保留」 |
| 实时价 | 措辞改成「季节系数估算价」；或真正接酒店价格 API 并写明数据源与更新频率 |
| 合规 | 页面 footer 加：Wikivoyage CC BY-SA 署名链接；Nominatim UA 加邮箱；评估是否缓存 Google/Places；Unsplash 按其 API 指南展示 |
| 性能 | 用户缓存、生成结果幂等缓存、向量服务独立部署、压测脚本纳入 CI 报告 |
| 作品集 | 删/脱敏 `.test-report` token；提供干净 `docker-compose` + `.env.example`；演示账号非 root MySQL |

### 3.1 建议优先级（1 小时 / 1 天 / 1 周）

**1 小时内（开源/投递前必做）**

1. 轮换全部线上 Key（LLM 优先）；
2. `.gitignore` 补 `.test-report/`、`.test-token.txt`、`.test-user.txt`；
3. 从本地删除或移出仓库目录的 token dump；
4. `/api/amap/geocode`、`/api/amap/poi` 改需鉴权。

**1 天内**

1. `photoCache` 上限 + TTL；
2. Java 启动校验：`AGENT_INTERNAL_TOKEN` 空则 fail-fast（或强制本机绑定）；
3. 登录限流：只信任受信代理 IP 的 XFF；
4. 注册统一错误文案 + 注册限流；
5. 密码复杂度策略。

**1 周内（作品集叙事升级）**

1. 收敛三编排或在 README 写清「有意保留」的边界与代价；
2. 补 JWT 吊销（logout + 禁用即时）；
3. 页面级第三方数据署名；
4. 把压测报告和「未验证项」清单写进 docs，答辩时可出示。

- 引用式生成与溯源；
- 查询路由与缓存边界；

### 4.3 答辩口径建议

1. **先自曝短板**：密钥、免鉴权代理、双后端代价、三编排未收敛；
2. **再讲修复**：对照 `docs/代码审计报告.md` 的 Critical/High 与你实际做的修复；
3. **最后讲 tradeoff**：为什么 LLM-only、为什么不缓存降级结果、为什么 N-1 晚。

面试官更信任「知道自己哪里弱」的候选人。

## 5. 高频压力面试题

### 5.1 业务/产品

1. 用户说「预算 2000 去杭州 3 天」，你系统从输入到 PDF 的完整链路是什么？哪一步最容易骗人？
2. 开放模式生成的 POI 库里没有，你怎么处理？「待确认」对用户有什么用？
3. N 天 N-1 晚，末日回程没有酒店——用户以为 3 晚怎么解释？
4. 「附近推荐」距离怎么算？步行时间来自哪？假坐标会怎样？

### 5.2 架构

5. 为什么 Vue→Java→Python？Java 不可以删吗？删了丢什么？
6. 为什么三套 workflow 没合并？现在改酒店口径要改几处？
7. Redis 缓存什么？和 Python 语义缓存谁管谁？缓存击穿怎么办？
8. 生成失败卡 status=3，恢复任务防死循环怎么做？二次失败用户看到什么？

### 5.3 RAG / Agent

9. RRF 怎么融合 BM25 和向量？为什么还要 rerank？
10. 语义缓存相似度 0.95 是怎么定的？误命中「杭州西湖」vs「惠州西湖」怎么办？
11. 引用三级匹配为什么禁止子串包含？举一个会翻车的例子。
12. Supervisor 补查和整体重生的区别？预算超了补查还执行吗？
13. `run_limits` 和 Prompt 约束有什么本质区别？为什么两个都要？

### 5.4 安全

14. `/api/amap/geocode` 为什么要登录？现在不登录会怎样？
15. 伪造 `X-Forwarded-For` 能无限爆破登录吗？
16. JWT 吊销怎么做？禁用用户为什么还要查库？
17. 前端 `localStorage` token 的 XSS 面你怎么评估的？
18. Java↔Python internal token 空字符串在生产会怎样？

### 5.5 第三方/合规

19. Wikivoyage CC BY-SA，你的衍生 POI 库开源吗？
20. Google Places 结果入库 30 天还合法吗？
21. 高德 Key 写在前端 JS 里，你靠什么防盗刷？

### 5.6 工程/你自己

22. 审计报告里修了这么多，为什么还留三编排不收敛？
23. 最近一个真 bug：现象、根因、怎么防再犯？

## 6. 一句话总评

> 工程完成度和问题意识在校招里**偏上**，RAG/降级/溯源叙事完整；但**密钥与免鉴权代理是硬伤**，**双后端 + 三编排会把架构题打成负分**，**「实时价/零幻觉/生产级」一类措辞会当场翻车**。  
> 答辩策略：**先自曝短板和 tradeoff，再讲你修了什么、还剩什么**——比全盘防御可信十倍。
